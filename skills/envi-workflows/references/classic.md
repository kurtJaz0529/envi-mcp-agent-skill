# Classic GUI 与实验报告

## 普通界面任务

先 `envi_classic_health_check`，再按当前 schema 用 `envi_classic_launch` 创建受控会话。只操作该服务启动的会话。

菜单先由 `envi_classic_list_menu_items` 查询真实名称与路径，再调用 `envi_classic_invoke_menu`。自绘界面需要受限 recipe 时，先观察当前窗口。操作失败后重新观察，不盲目重复坐标。

普通查看或诊断不自动要求实验指导书、模板及全套证据登记。诊断可使用服务支持的 `mode="diagnostic"`；结束后关闭自己创建的空诊断会话，不接管用户已有 ENVI 进程。

Classic 是桌面程序。需要真实截图时使用原生界面；优先后台执行的偏好不能被解释为将 ENVI 转移进浏览器或伪造界面证据。

## 完整实验报告

当用户确实要求按指导书交付实验报告时，使用可用的 `envi-classic-lab-automation` 与 `remote-sensing-report` 技能，并读取该任务对应的指导文件。核心顺序为：

1. 读取指导书、数据、报告模板，先拟定步骤和截图清单。
2. 健康检查、启动受控会话；登记实际输入及哈希。
3. 在任何正式证据截图之前冻结完整阶段计划。
4. 按真实菜单和参数执行。每个阶段及时捕获原始证据；参数设置与结果查看分开登记。
5. 登记真实输出文件、哈希和必要统计。
6. `envi_classic_finalize_evidence` 按冻结计划验收；只有 `complete=true` 才进入完整报告交付。
7. 继承用户模板生成报告，渲染检查 Word/PDF；方法、图题和统计与证据记录对应。

报告使用服务捕获或用户提供的原始截图，不通过裁剪、合成、重绘或增强制造步骤证据。需要图像对照时在文档中放置多个独立原图对象。

证据缺失就补做对应步骤；不通过删阶段、复用一张图冒充多步或调低门槛宣称完成。依赖缺失时说明可交付的计算结果或证据包，以及仍未完成的报告环节。
