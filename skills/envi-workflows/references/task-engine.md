# Task Engine 调用与后台计算

## 可复用的调用顺序

1. `check_envi_connectivity()` 或 `find_envi_taskengine()`：确定引擎和环境。
2. `list_envi_tasks(filter_str=...)`：找到本机精确名称。
3. `get_envi_task_info(task_name=...)`：确认输入、输出、类型、必填项与具体语义。
4. 建立独立输出目录；调用 `run_envi_task(task_name=..., params=..., timeout=...)`。
5. 检查真实返回的 `outputParameters` 和文件存在性，再验证像元与地理信息。

健康检查只在当前任务需要确认环境或状态变化时执行；不必为同一已稳定运行的流程重复启动诊断。

## 经验与兼容性

- 官方 `envipyengine.Task.execute` 接收参数字典。有些上游包装先设置对象属性再调用 `execute()`，在真实 SDK 上会失败。修改或更新包装时保留基于签名的兼容与返回 `outputParameters` 的提取。
- 读取 schema 后再构造输入。支持栅格工厂的参数可能使用 `{"factory":"URLRaster","url":"..."}`；只有实际参数定义支持时才这样传，不把所有文件参数都强行改为同一种对象。
- `OUTPUT_RASTER_URI="*"` 在支持该约定的任务中表示虚拟栅格；它不保证生成磁盘文件。需要持久产物时使用实际路径并检查输出。
- 名称中出现 `RadarBackscatter`、`radar` 或 `SAR` 不能证明已安装完整 SARScape/InSAR 工作链。逐项核对所需任务和许可。
- 逻辑包装可能使用模糊名称寻找任务。优先使用查到的精确名称；核对参数映射后再执行。
- 线程超时不能保证已终止底层 Task Engine。先检查仍在运行的任务及部分文件，避免同名输出冲突。

## 结果验收

- 波段计算：在小型合成输入上验证预期像元值，再使用实际数据；不能仅检查文件生成。
- 配准、重采样、裁剪和差分：检查 CRS、transform、分辨率、范围、维度；重采样到相同网格不等于纠正了真实几何偏移。
- NoData 和掩膜：验证有效像元交集与输出忽略值。比较两幅影像时使用共同有效位置，不能分别压缩后按位置配对。
- DEM 精度：数组尺寸相同不够；还需共同网格、相同高程单位与适用的高程参考。
- 面积：区分经纬度与米制像元，按合适投影统计；不能直接把经纬度像元宽高当作平方米。

失败时保存错误、实际参数和部分产物状态，不把计划中的输出路径当作已经存在的结果。恢复执行前核实上游产物仍存在且满足当前步骤输入。
